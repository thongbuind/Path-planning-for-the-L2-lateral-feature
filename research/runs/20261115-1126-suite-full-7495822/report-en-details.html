If required a_y > aysmax at a point in the 0–1 s segment of the path while HWA is in control, path a_y at that point shall be ≥ aysmax − epsilon_ay

PP-SWR-007

When a front tire starts to touch the marking while HWA is in control and maximum required a_y > aysmax, lateral_limit_reached shall already be true

PP-SWR-008

The time from when maximum required a_y drops below aysmax until lateral_limit_reached clears should be short

PP-SWR-009

The planner shall publish the same lateral_limit_reached value in PathStatus and LateralLimits for the same cycle

PP-SWR-010

The planner shall publish Trajectory and PathStatus every cycle

PP-SWR-011

Trajectory shall follow the format in the Interface Control Document: 31 points at 0.1 s intervals, spanning 0–3 s, frame_id = base_link

PP-SWR-012

Trajectory header.stamp_us shall be the time represented by the path, with lane model latency compensated

PP-SWR-013

Additional lateral deviation relative to the zero-latency case should be small when camera latency is 0–200 ms with ±20 ms jitter

PP-SWR-014

header.counter shall increment by 1 after every message and wrap over 0–255

PP-SWR-015

The planner shall record computation time for every cycle

PP-SWR-016

The 99th percentile of computation time per cycle should be low

PP-SWR-017

The planner shall accept a lane model with any view_range_end > view_range_start for each marking and road edge. A view range beyond 126 m shall not invalidate the input

PP-SWR-018

Trajectory.observed_horizon_s shall be no more than 0.1 s later than the point in time when the path leaves the view range reported by the lane model frame used in that cycle

PP-SWR-030

The planner shall select the function in control in the priority order ELK > LKA > HWA, considering only functions with state = REQUEST

PP-SWR-031

When the function in control changes, the path shall satisfy PP-SWR-100 to 102, except when LKA or ELK starts and the actual vehicle deviates from the previous path by more than 0.1 m or 0.1 m/s. In that case, apply PP-SWR-080

PP-SWR-032

When the LKA or ELK termination conditions have held continuously for T_end_hold, the planner shall set that function's phase to COMPLETED

PP-SWR-033

After COMPLETED, the planner shall select the function in control according to PP-SWR-030 from the functions still in REQUEST, excluding the one just marked COMPLETED. If no function remains, select NONE

PP-SWR-034

If the function just marked COMPLETED remains in REQUEST, the planner shall not start a new intervention for that function until its state leaves REQUEST and returns to it

PP-SWR-035

Each new LKA or ELK intervention shall have the same limits as the first, regardless of the number of prior interventions

PP-SWR-036

When the intervening function leaves REQUEST mid-intervention, the planner shall transition from the current state to the function selected under PP-SWR-030 from those still in REQUEST

PP-SWR-037

When the intervening function leaves REQUEST mid-intervention through a valid message and no eligible function remains, the planner shall report active_function = NONE with path_valid = true if the required inputs remain valid

PP-SWR-038

The planner shall reflect changes in FunctionRequests in its output within one cycle of receiving the message

PP-SWR-039

While driver_override = true, the start of the path shall match the vehicle's current lateral position with an error of ≤ 0.05 m

PP-SWR-040

When driver_override changes to false while HWA is in REQUEST, the start of the HWA path shall match the vehicle's lateral position at that time with an error of ≤ 0.05 m

PP-SWR-041

The planner shall keep each function's phase at COMPLETED until that function leaves REQUEST

PP-SWR-042

When HWA leaves REQUEST and no function is in REQUEST, the planner shall set active_function = NONE and keep path_valid = true

PP-SWR-043

While path_valid = false, active_function shall equal NONE

PP-SWR-044

When inputs recover after path_valid = false, the start of the new path shall match the vehicle's actual lateral state within the tolerances in PP-SWR-080

PP-SWR-045

After input recovery, the planner shall start an LKA or ELK intervention only after the state of that function leaves REQUEST and returns to it

PP-SWR-046

If VehicleStateEstimate becomes invalid during LKA or ELK intervention, the planner shall continue that intervention path until it ends

PP-SWR-047

While the lane center can only be inferred from boundaries outside the ego lane, the planner shall not select LKA or ELK. Road-edge ELK is allowed if the hazard-side boundary of the ego lane is a MEASURED edge with confidence ≥ conf_edge and a reliable opposite boundary or stored lane width is available
